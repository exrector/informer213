# Informer 213: прошивка по уже установленному USB-кабелю

**ПОДТВЕРЖДЕНО НА РЕАЛЬНОМ УСТРОЙСТВЕ 24.10.2026.**

Teensy 4.1 внутри Informer 213 можно перепрошить через тот USB-кабель, которым клавиатура уже подключена к Mac mini AK. Корпус не вскрывали, кабель не меняли, кнопку Program на плате не нажимали, компьютер не перезагружали. Через SSH по LAN записана прошивка v3.1; клавиатура сама вернулась в рабочий USB-режим.

Это проверенный способ обслуживания установленного устройства, а не предположение. Старое утверждение README о невозможности программного входа в загрузчик для этой конфигурации ошибочно.

## Что установлено

- Плата: **Teensy 4.1**; USB Serial + Keyboard + Mouse + Joystick (`serialhid`).
- USB serial number: `12870050`; во время проверки порт `/dev/cu.usbmodem128700501`.
- Рабочий исходник: `informer213-v3/informer213-v3.ino`; версия **v3.1**.
- Матрица сохранена: пины строк 33–39, столбцов 0–12; изменение только назначения замка и логики блокировки.
- Замок на пересечении **пинов 39 и 10** переключает блокировку всей клавиатуры; больше не отправляет Command.
- При включении блокировки отпускаются обычные и мультимедийные HID-клавиши; буквы, цифры, модификаторы, медиакнопки и Fn-комбинации перестают отправляться. Сам замок остаётся доступен для разблокировки.
- При снятии блокировки уже удерживаемые кнопки не отправляются сами: их нужно отпустить и нажать заново. При включении питания клавиатура разблокирована.
- По USB Serial символ `?` возвращает `INFORMER213 v3.1 LOCK=ON/OFF`; эта диагностика не переключает замок.

## Как прошивалось

1. На MacBook собран HEX именно для Teensy 4.1:

   ```sh
   arduino-cli compile --fqbn 'teensy:avr:teensy41:usb=serialhid,speed=600,opt=o2std,keys=en-us' --build-path /путь/к/build informer213-v3
   ```

2. HEX и Intel-загрузчик переданы по SSH на Mac mini AK в `~/LOST-tools/informer-lock/`.
3. CLI-загрузчик ожидает HalfKay с `--mcu=TEENSY41 -w -v`.
4. Через уже существующий serial-порт отправлен **штатный запрос USB CDC: скорость 134 бод**. Именно он переводит работающую прошивку Teensyduino в HalfKay. Скорость 115200 используется для обычной диагностики, не для этого запроса.
5. Загрузчик записал HEX и вернул плату в рабочий режим.
6. По вернувшемуся serial-порту прочитан ответ v3.1. В логе также зафиксированы реальные нажатия замка и переходы LOCK=ON → LOCK=OFF.

Повторяемая команда (не запускать для простого чтения статуса — она перепрошивает устройство):

```sh
python3 tools/usb-programming/flash-macos.py \
  --port /dev/cu.usbmodem128700501 \
  --loader "$HOME/LOST-tools/informer-lock/teensy_loader_cli-intel" \
  --hex /полный/путь/informer213-v3.ino.hex
```

Команда выполняется **на Mac mini, к которому физически подключена клавиатура**. Путь порта нужно сверять перед повторной прошивкой; его номер может измениться. В репозитории сохранён скрипт, но повторно во время документирования устройство не прошивалось.

## Особенность загрузчика на macOS

В Teensy Loader CLI 2.3 параметр `-s` на macOS **не реализован**: он выводит `Soft reboot is not implemented for OSX`. Это ограничение CLI, а не платы или установленного кабеля. Поэтому запрос 134 бод и загрузчик запускаются раздельно.

Оригинальный CLI открывает общий HID Manager. В использованной сборке выбор ограничен только интерфейсом программирования PJRC: **VID 0x16C0 / PID 0x0478**. Это устранило `Error opening HID Manager` без изменения разрешений macOS и без sudo. Патч: `tools/usb-programming/loader-macos-match.patch`.

Для Mac mini использована сборка **x86_64**, а не ARM-бинарник Homebrew с MacBook. Исходник PJRC: https://github.com/PaulStoffregen/teensy_loader_cli (GPLv3). Сборка после применения патча:

```sh
clang -arch x86_64 -O2 -DUSE_APPLE_IOKIT teensy_loader_cli.c \
  -framework IOKit -framework CoreFoundation -mmacosx-version-min=10.15 \
  -o teensy_loader_cli-intel
```

Последующее чтение с установленного устройства:

```text
PRESS row=39 col=10
INFORMER213 v3.1 LOCK=ON

PRESS row=39 col=10

```

SHA-256 записанного HEX:

```text
71bca929f3ae995bddeb4330a4dbfea94a0fc18e3b834ed4bfbc827e033d257c
```

Блокировка и снятие зажатых клавиш также проверены тестом с имитацией матрицы. Физическое нажатие всех остальных клавиш при включённом замке по этим логам не подтверждалось — не путать с проверкой загрузки и самого переключения замка.

## Когда всё же нужна физическая кнопка

Программный способ требует, чтобы текущая прошивка отвечала по USB и сохраняла поддержку USB Serial/Teensyduino. Если прошивка зависла или USB отключён ошибочным кодом, запрос 134 бод может не сработать; тогда аппаратная кнопка Program остаётся способом восстановления. Обычная блокировка клавиш в v3.1 не отключает USB Serial и не мешает повторной прошивке по установленному кабелю.
